# FaithSift

[中文](README.md) | **English**

> Formerly named CiteCheck (renamed to FaithSift) on 2026-10-27 due to name
> collisions — see [CHANGELOG](CHANGELOG.md). Legacy `CITECHECK_*` environment
> variables are still honoured as fallbacks.

Sentence-level **citation-faithfulness checker for RAG answers**. Feed it an answer
(md/txt) plus the sources your RAG pipeline retrieved from; it splits the answer into
claims and labels each one:

- **supported** — the sources clearly contain this fact (paraphrase & translation tolerant);
- **contradicted** — the sources state something conflicting about *the same fact*
  (different number, reversed direction, swapped entity, different unit);
- **unsupported** — the sources are silent: no evidence either way.

Keeping `unsupported` as a first-class label is the whole point. Most hallucination
checkers are binary and conflate "got it wrong" with "invented a topic the sources never
covered". Separating them is what makes RAG hallucination governance actionable.

**Things you should know:**

1. 100% on the synthetic set is *not* real-world performance. It is generated by three
   rules (extract verbatim / alter a number / template on an absent topic), so it is
   lexically friendly by construction. It only proves refactors do not break what worked.
2. The hard set is now **150 claims** written by one person, each with a `rationale`, and
   **deterministically rebuildable** (`python -m faithsift gold` is idempotent, fixed seed).
   It exposes capability gaps; it is still not a multi-annotator industrial benchmark.
3. **Modal tampering is a total blind spot for the lexical engine (0%)**: turning "may /
   debated / multi-factor" into "certain / settled / sole cause" carries no lexical or
   vector signal — only the LLM judge catches it (83%). This is the biggest new gap the
   expansion exposed, and it is **reported as-is; the gold labels were not bent to flatter
   the implementation**. "Adjacent topic vs conflict" (lexical 64%) is the same kind of hard case.
4. **LLM judge re-measured for v0.3** (2026-10-28): synthetic 178 **99.44%**, hard 150
   **99.33%** (the single miss is a borderline uniqueness/modal case), ≈**¥0.54** total
   (DeepSeek, logged per call in `results/cost_ledger.jsonl`); artifacts in
   `results/v03_{gold,hard}_llm.json`. The v0.2 results (`gold/validation_*_llm_v0.2.json`,
   49-claim old hard set) are kept for comparison.

## Dual judges × three retrieval channels

| Axis | Option | Dependency | Use case |
|---|---|---|---|
| Judge | `heuristic` | zero API, local rules | CI gates, offline checks, batch regression |
| Judge | `llm` | DeepSeek structured-JSON judge | semantic verdicts: paraphrase, entailment traps, cross-lingual |
| Retrieval | `lexical` | zero deps (BM25 + numeric + concept lexicon) | default |
| Retrieval | `hybrid` | needs an embedder; BM25 + numeric + dense | open domain, heavy paraphrase |
| Retrieval | `dense` | needs an embedder; dense cosine + numeric | semantic recall |

The vector channel is never mandatory: the core package imports and runs the lexical
engine without any vector dependency (strict isolation). `--embedder local` uses a
**local offline ONNX multilingual model** (fastembed, no torch); it downloads once via the
HF mirror (`HF_ENDPOINT`) and then runs fully offline, reusing the disk cache. If the
dependency is missing or the model fails to load, it prints a clear message and **degrades
to `lexical`** instead of crashing (the same philosophy as hybrid-without-embedder).
`--embedder hashing` is a zero-dependency stand-in that exercises the plumbing (no cross-lingual).

```bash
pip install -e ".[semantic]"                     # install the local vector backend (fastembed)
export HF_ENDPOINT=https://hf-mirror.com         # CN mirror (optional, first download only)
python -m faithsift check answer.md --sources gold/sources \
    --retriever hybrid --embedder local          # BM25 + numeric + dense fusion
```

## Quick start

```bash
python -m venv .venv && .venv/Scripts/pip install -e ".[dev]"
python -m pytest tests/ -q                       # 89 offline tests, zero API (vector e2e skips without a model)

python -m faithsift gold                         # rebuild both gold sets (deterministic)
python -m faithsift validate --dataset gold      # synthetic: regression floor
python -m faithsift validate --dataset hard      # hard: capability gaps

python -m faithsift check demo/sample_answer.md --sources gold/sources \
    --mode heuristic --out results/check
# -> results/check.{md,html,json}
```

## CLI

```text
faithsift check <answer> --sources <dir>
    --mode heuristic|llm|both
    --retriever lexical|hybrid|dense
    --embedder hashing|local|<model>   vector backend (local = offline ONNX multilingual)
    --top-k N --out results/check
    --fail-under 0.9                 faithfulness below threshold -> exit 3
    --fail-on-contradicted           any contradicted claim      -> exit 4
    --json

faithsift gold
faithsift validate --dataset gold|hard --mode heuristic|llm
    --min-accuracy 0.85              accuracy below threshold -> exit 5
```

Exit codes: `0` ok · `2` usage error · `3` faithfulness gate · `4` contradiction gate
· `5` accuracy gate · `6` missing credentials.

## Judge contract

- **supported**: the evidence clearly contains the claim's core fact (entities and
  relations agree; non-numeric paraphrase and translation count); list every chunk index
  needed when a claim is supported by more than one chunk.
- **contradicted**: the evidence states a different value for the *same fact* — number
  mismatch, reversed direction (rise/fall, above/below), swapped entity, different unit.
- **unsupported**: the evidence is silent — neither supports nor conflicts.

Three hard rules:

1. **No logical entailment on numbers.** Source says "above 200°C", claim says "above
   180°C" ⇒ `contradicted`, even though it is logically implied. Changing a number is tampering.
2. **Adjacent topic is not a conflict.** The corpus discusses a neighbouring subtopic but
   not this fact ⇒ `unsupported`.
3. **Support must cite evidence.** Every verdict carries `evidence_idx` (an array for multi-hop).

## Design notes worth knowing

**Numbers are language-agnostic.** Numbers survive translation, so a Chinese claim about
"一爆 196–205°C" retrieves the English paragraph containing 196/205. This single change
moved the LLM demo from 5/8 to 8/8.

**Chinese numeral normalisation.** "两千", "四到六", "一成", "10 万", "1.9 million" and
"2,000" are all normalised to plain digits before matching — otherwise spelled-out numbers
in Chinese answers break both retrieval and the numeric consistency check. Approximation
markers such as "数百" are deliberately not converted.

**A concept lexicon fills the cross-lingual gap.** With numbers only, a digit-free Chinese
claim can never retrieve English evidence. `faithsift/lexicon.py` maps Chinese and English
surface forms onto shared concept tokens (`茶树`/`tea` → `tea`, `一爆`/`first crack` →
`first_crack`): ~250 surface forms, ~120 concepts, covering the six bundled domains.

**An entity gazetteer prevents entity swaps.** A claim naming Amsterdam while "invested 2
billion DKK since 2005" belongs to Copenhagen has perfect numbers and perfect topical
overlap — and is still wrong. Chunks that name *only other* entities are demoted to
corroboration; if all the claim's numbers live there, the verdict is `contradicted`
(entity swap).

**Multi-hop really needs two chunks.** The judge does not accept "some paragraph is
related": a second chunk is only admitted when it adds enough new coverage and the union
clears a threshold.

**Cost fuse.** `results/cost_ledger.jsonl` records every call, hard-capped at ¥12
(`FAITHSIFT_CAP`; the legacy `CITECHECK_CAP` is still read as a fallback),
raising `BudgetStop` at the limit.

## Layout

```text
faithsift/claims.py     zh/en sentence-level claim splitter
faithsift/evidence.py   source loading, chunking, tokenisation
faithsift/lexicon.py    bilingual concept lexicon + entity gazetteer
faithsift/numbers.py    Chinese numeral & magnitude normalisation
faithsift/retrieval.py  BM25 + numeric invariance + optional dense signal
faithsift/embed.py      optional embedders (OpenAI-compatible / local offline ONNX / hashing / cache)
faithsift/judge.py      LLM judge + heuristic judge (multi-hop aware)
faithsift/pipeline.py   end-to-end pipelines, gold validation, CI gates
faithsift/report.py     md / html / json rendering
gold/                   both gold sets + 6 bilingual source docs + validation artifacts
demo/                   sample answers and rendered reports
scripts/gap_report.py   dev helper: per-category error listing
tests/                  89 offline tests (vector e2e skips without fastembed/model)
```

## Secrets & security

Real keys never enter the repo. Resolution order:

1. `DEEPSEEK_API_KEY` environment variable
2. the file pointed to by `FAITHSIFT_ENV_FILE` (can live outside the repo; the
   legacy `CITECHECK_ENV_FILE` still works as a fallback)
3. `.env.local` (gitignored, local only)
4. `.env` (placeholders only)

`tests/test_security.py` scans repository files for real-looking secrets and verifies
`.env` is not tracked by git. CI runs it as a separate job.

> If a real key was ever written to a file, **rotate** it in the console — deleting the
> file is not enough, copies already distributed are out of your control.

## Relation to prior work (honest positioning)

Full survey (40+ entries, each with verification status and links): [docs/survey_faithfulness_landscape.md](docs/survey_faithfulness_landscape.md).

- **Not claimed as novel**: the split→retrieve→judge pipeline is an established paradigm since 2023 (FActScore, SAFE, RAGAS, DeepEval, ALCE); the "evidence-silent" third class has precedents in FEVER (NotEnoughInfo) and NLI (neutral). The former name "CiteCheck" collided with a 2025 PKU paper of the same name (arXiv:2502.10881, Chinese citation-faithfulness dataset) — the reason this project was renamed **FaithSift**; no code/data lineage from that work.
- **Defensible differentiators** (within the verified survey scope): ① a **pure-lexical zero-API judge** — existing low-cost checkers are neural small models; an auditable lexical+numeric judge has no found counterpart; ② **seed-fixed deterministic gold used to audit the judges themselves** (arXiv:2607.20527 documents severe disagreement among neural judges, motivating this); ③ a **zh-claim→en-source cross-lingual lexical retrieval pipeline** (numeric invariance + concept lexicon, no identical design found); ④ engineered multi-hop evidence judging (lineage: FEVEROUS).
- Citation discipline: 4 survey entries marked "unverified (training memory only)" must be human-checked before formal citation.

## Known limitations (v0.3 status)

**Fixed since v0.2 (moved out of limitations):**

- ~~Heavy same-language paraphrase~~ → with the vector channel (`--embedder local`), the
  hard-set "Chinese paraphrase" category rises from 94% (lexical) to **100%**; paraphrases
  with almost no surface overlap are caught by the semantic-cosine fallback.
- ~~Adjacent topic judged as conflict~~ → "Dutch helmet law started in 2010" (the corpus
  actually means Australia in the 1990s) is now `unsupported`: a missing number only counts
  as a conflict when a competing value exists in the **same fact slot + same entity**.
- ~~Direction without numbers (Agtron)~~ → added roast light/dark qualitative-scale antonym
  detection, so "Agtron 数值越大越深" vs "higher numbers indicate lighter roasts" is now `contradicted`.

**Still open (listed honestly):**

- **Modal tampering is a total lexical blind spot (0%)**: escalating "may / debated /
  multi-factor" to "certain / settled / sole cause" carries no reliable lexical or vector
  signal — only the LLM judge handles it (83%).
- **Subtle adjacent topics can still be "multi-hop"-supported (lexical 64%)**: when two
  chunks each cover half of a claim's concepts (e.g. "Singapore ranks first globally in
  green-roof coverage"), the lexical engine falsely says `supported`. It is structurally
  identical to a faithful multi-hop claim at the lexical level; telling them apart needs
  semantic entailment (LLM judge: 100%).
- **Cross-lingual sparse concepts**: a zh claim over an en source with too few mappable
  concepts (e.g. "a colony has 200k–800k individuals in temperate regions") gets too-low
  lexical coverage; the vector channel helps retrieval but the judge's coverage is still
  mostly lexical/conceptual.
- **The concept lexicon covers six domains only** — use `--retriever hybrid --embedder local`
  or `--mode llm` for open corpora; out-of-lexicon words degrade gracefully to raw lexical tokens.
- **Limited direction word list**: reversals are missed when the direction word sits far from
  the number/concept it modifies, or uses a bare unlisted word like "低/高" (hard-set direction: lexical 86%).
- **Still single-annotator gold**: 150 hard claims expose gaps and give per-category
  strengths, but cannot yield confidence intervals, and there is no second-annotator Kappa check.
